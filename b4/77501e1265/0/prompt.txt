## Verdicts

1. **`locators` vs `locators[]`** — `locators[]` is **correct**; plain `locators` is **wrong**. The hypothesis in `tools/projects.py`'s docstring is backwards. A single plain `locators=&lt;one&gt;` returns `400 "expected array, received string at \"locators\" or ... expected \"all\""`; `locators[]=&lt;one&gt;` returns `200 {"created":1,"errors":{}}` and the assignment verifiably takes effect. Plain *repeated* (`locators=a&amp;locators=b`) works — classic `qs` single-vs-array parsing — so the bug only bites one-project calls. Same result for `PUT /v2/projects/labels` and `GET /v2/projects`; `DELETE /v2/projects` tolerates both. `POST /v2/projects`'s JSON body correctly uses plain `locators`.
2. **Package labels** — "blank for all versions" means **omit the key** (stores `null`); `""` is stored literally and matches nothing, `null` is a `400`. `scopeId` must be **absent** for `org` scope (sending it → `500`) and **present** for `project`/`revision` (omitting → `500`). `POST /organizations/labels` with `{}` → `400 "Create label missing required param: 'label'"` — the spec's empty `required` list is a defect.
3. **`GET /counts/builds`** — both defects confirmed: returns a **bare JSON number** (1-byte body), and `locator`/`projectId` is required with exactly the 400 text the spec's own example shows.
4. **Org settings propagate** — `DESTRUCTIVE` is right. A per-project override was set, propagated, and **destroyed**, while a second override not named in the key list survived. Propagation is scoped to the named keys and does not alter the org defaults themselves.
5. **`POST /oidc/token-exchange`** — a *valid* `Authorization` header is ignored (byte-identical `400`s with and without it), but an *invalid* one returns `401` before the endpoint's own validation. So the header is not inert: a caller with no FOSSA token — the actual use case — cannot send a placeholder. The success path is unreachable without an OIDC trust relationship; that remains unresolved.
6. **`github-app/installation-url`** — `302`, empty body, `Location: https://github.com/apps/fossa-integration/installations/new`, byte-identical across calls, no `state`/nonce. Stable and public: a tool should not follow the redirect, just return the header.

## Highest-value finding

**The `todos` obligation set is incomplete and fails silently.** The gaps document's claim that it is the highest-value item holds, but its framing does not. FOSSA's obligation table is keyed on exact license ids, and it has **no entry for any `-or-later` copyleft variant** — `GPL-3.0-or-later`, `LGPL-3.0-or-later`, `LGPL-2.1-or-later` all produce zero obligations, while `GPL-2.0-only` and `LGPL-3.0-only` produce full ones including `Disclose Source`. Also missing: every exception-bearing id, plus `proprietary-license`, `public-domain`, and other non-canonical ids. On one project 17 of 33 licenses had no obligations at all; on the other, 6 of 18, including an `LGPL-3.0-or-later` spanning 14 dependency revisions.

Taken at face value, this endpoint would tell `fossa-license-review` that a project full of `GPL-3.0-or-later` has no copyleft obligations. The tool must diff `todos` against `deeplicenses` and return the uncovered licenses as a first-class field.
